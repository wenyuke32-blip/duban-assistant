# 安装部署与数据恢复

## 运行条件

Python 3.10+；openpyxl、python-docx、matplotlib、pypdf；中文字体（思源黑体/Noto Sans CJK/微软雅黑）；POSIX fcntl文件锁、原子rename、符号链接和文件fsync。已经在当前Linux开发环境实际执行文件读写，但没有验证MobileWork具备这些条件。**Windows宿主或不允许Python/符号链接的环境尚不支持本内核直接运行。** 先运行能力探测，不能仅因本地可用就声称平台可用。

解压项目，切换项目根目录：

```bash
python tools/check_environment.py
python -m duban init --workspace /平台持久化路径/督办数据
```

如依赖缺失，先按平台规则配置受支持的依赖环境。仅在平台允许安装时使用 `python -m pip install -r requirements.txt`。不要假设可以联网安装或擅自修改宿主环境。Python执行被禁用时需要平台提供受支持的运行容器/脚本能力；不要只复制SKILL.md后声称可运行。

将SKILL.md及项目目录按MobileWork实际的Skill导入规范安装（目前未获得该平台的专用打包规范，所以ZIP是完整源码包，不宣称是一键导入格式）。保持duban包、prompts、docs相对路径完整。宿主原生工具执行JSON文件创建、任务理解和研判；真实邮箱适配步骤见邮件与宿主适配.md。

## 工作空间结构

- 督办管理总台账.xlsx：唯一业务台账，9张表，其中包含附件要求的7张。
- .run.lock：同一工作空间命令行运行串行化，确保执行摘要不混入另一次运行。
- .ledger.lock：并发执行互斥锁，不要手工删除运行中的锁文件。
- .recovery/督办管理总台账.last-good.xlsx：上一版已校验台账，包含敏感业务信息，需同等访问控制。
- reports：符号链接，指向最新报告版本目录，合计10份文件。
- .reports-*：报告暂存/当前版本目录，成功切换后删除上一版；异常进程退出可能留下未引用暂存目录。

不要让多台机器同时通过不支持可靠POSIX锁的网络文件系统编辑；不要在程序执行期间用Excel桌面编辑台账。办公软件外部修改不参与程序锁，需管理员安排互斥维护窗口。程序检测到外部新增未知工作表时拒绝写入，避免静默丢失；已知表的外部人工格式不保证保留；本版本固定schema，不支持手工改表头或增加业务表。导入外部台账请用import。

## 安全写入与恢复

每次事务：获取锁→读取并验证现有台账→清理超72小时详细记录→增量操作→同目录临时xlsx→重新打开校验→fsync→备份旧有效台账→原子替换→同步目录。写入前失败不替换原文件。主文件损坏时直接报错，不自动初始化覆盖。

恢复时停止自动任务，复制损坏文件到管理员安全保管位置，检查.recovery中的备份可打开且任务数量合理，再由管理员把备份复制到固定台账位置。保留损坏副本以便核对遗漏。恢复可能回退一版业务更新：重跑邮件同步时核对去重记录和已发送记录；不能盲目重发已发送邮件，未知项先reconcile。

报告先完整生成10件并逐件校验，再原子切换reports链接；失败时仍指向旧报告。V1.1通过.report-publication.json日志和事务回调协调报告与台账：未提交台账时恢复旧报告，已提交则保留新报告并清理旧版。已实际测试发布窗口子进程退出后重启恢复；这不是对物理断电或不可靠网络文件系统的保证。不要手动删除有效报告。发送前逐个校验附件hash，文件被覆盖后旧队列失效，需重新入队并授权。

## 隐私与日志

工作空间只允许管理员和经授权运行身份访问。台账包含业务、联系人与邮件ID；不在本项目保存邮箱认证凭据。平台应提供磁盘加密及备份权限。本项目日志只记录动作、计数、非敏感错误类型和必要业务证据，不记录认证响应或完整接口异常。详细进展/AI事件history仅72小时；主任务最新结论、累计延期/重开、办结日期长期保留。邮件去重、发送状态、待确认、执行摘要长期保存以保证可恢复性；不会把可识别详细历史复制到运行摘要中。

## 扩展与版本

schema_version=1，升级前先备份；本版本没有自动迁移外部/旧版schema。模板在templates中，仅在没有台账时使用；不能将空模板覆盖生产台账。适配器作为可信部署代码，与SKILL.md一同受企业代码审查和权限保护。

V1.1提供显式recover命令（停止自动任务后使用），先验证有效备份并保留原文件副本，再原子恢复。详细操作见部署操作说明_V1.1.md。
