# V1.2原生协作验收报告

日期：2026年10月17日（北京时间）。默认架构已改为MobileWork自身大模型分析，直接自然语言调用cmcc-mail。**不需要自建模型/邮箱API或Python桥接模块。** V1.1把缺少这类模块作为默认阻塞条件的结论，不再适用于V1.2。

## 实现变化

- native.py实现sync→analysis→report→ready→send→complete的持久化原生流程。full/sync/scan/warn默认返回宿主的原生执行动作，MobileWork读取SKILL.md持续执行；不是仅在文档里写功能。
- native-mail校验宿主取得的邮件与语义计划，原生模型结果通过native-analysis实际进入固定台账。任务指纹变化时拒绝过期写入。
- native-report-context提供范围内的真实统计/证据；native-report-text保存MobileWork自行撰写的有引用复盘，reports.py实际嵌入Word，并保留统计与图表。
- native-next-send先记录关联状态，再输出精确自然语言cmcc-mail委托；native-send-result保存Skill实际语言回复。平台没返回消息ID时不伪造ID。
- 等待确认继续原Skill对话；结果未知只核实原调用；重复回执不重复计数，重复流程不重复入队/发送。模拟研判和复盘不能直接被正式流程复用。

## 1. 已通过实际本地运行验证

固定Excel跨次运行、任务新增/更新/归档/重开、日期及统计、预警队列、文件锁、10份Excel/Word真实图表与复盘文字嵌入、原生阶段检查点、请求快照/回执关联验证、恢复与幂等代码均实际运行。所有输入任务为合成样本，不代表真实公司业务。

原有业务50项测试及新增11项原生测试，共61项单元/集成测试通过；其中包含模拟与故障注入，不能把61项都叫真实业务验证。最终原生专项11项又单独复测通过。日志见本地测试结果.txt、evidence/regression-61-tests.txt和native-v1.2-tests.txt。

另执行不加载任何--adapter模块的58次独立CLI交接，10件报告实际打开，Word确实含宿主交接的复盘段落；重复邮件、重复回执、未知结果核实及相同快照重跑均按预期执行，重跑额外发送0。

## 2. 仅通过模拟验证

上述58次交接中的AI分析、复盘正文、邮件查询结果及cmcc-mail语言回复由脚本固定提供。流程使用--simulation明确标记：模拟回执11条，真实邮件调用0、真实模型调用0。

这证明程序能接收、校验和持久化原生交接结果，不能证明MobileWork实际推理质量、cmcc-mail实际执行或收件箱收到。原生流程不需要测试fixture_adapter；run_native_acceptance.py没有加载自建适配模块，也没有访问模型或邮箱网络服务。

## 3. 需在MobileWork实际运行，当前尚未验证

用户已明确MobileWork自身有大模型、cmcc-mail可自然语言调用，本版按该能力实现。当前聊天仍未接入你的MobileWork会话，无法在这里完成真实执行验收；这不是否认平台具备这些能力。

仍需在目标平台验证：脚本/依赖和持久化目录、宿主自身模型的真实匹配/拖延分析/复盘效果、语言委托cmcc-mail的搜索/正文/附件、企业通讯录及本次授权、真实附件发送/已发送核实、宿主重启后恢复。直接在MobileWork执行完整流程即可取得实际结果，不需先提供或编写API桥接。

权限遵循cmcc-mail自身规则：若需确认，等待确认；若有正式预授权，按其实际机制执行。配置联系人本身不构成持续发送授权。

## 4. 尚未覆盖的扩展

内置扫描PDF OCR、旧xls/doc转换、Windows原生兼容，以及所有恢复副本统一72小时脱敏清理未在当前包实现。可使用平台合法原生文档能力取得可处理资料，但不能宣称本包已实测这些扩展。

“生产模型API绑定/邮箱HTTP绑定”不再是本版未实现项，因为默认路线根本不需要它们；实际宿主推理与Skill执行属于第3类待运行验证。
