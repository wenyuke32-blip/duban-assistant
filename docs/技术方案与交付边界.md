# 技术方案与交付边界

## 职责分工

MobileWork原生：管理员交互、大模型自然语言理解与研判、合法文件工具、cmcc-mail认证及工具、平台自动任务配置。已提供相应SKILL指令和结构化输入输出合同；宿主真实能力需联调。

Python内核：固定台账读写、保护字段/日期验证、事务/备份、任务增量更新与归档、邮件ID去重、待确认管理、风险结论验证、确定性预警、发送状态机、真实统计与Excel/Word图表。代码中不内置邮箱API地址或外部模型服务，不需要创建独立定时器。

## 交付构成

- SKILL.md：13个标准中文入口，增补批量、恢复、联系人、发送核实等入口。
- duban/：完整可执行核心、命令行、宿主适配调度、报告生成。
- templates/：零任务空白统一Excel台账，包含要求的7表及发送记录/执行记录两表。
- prompts/：管理员理解、邮件拆分匹配、深度研判、结构化schema和平台自动任务提示词。
- docs/：安装、恢复、日常用法、邮件对接、预警模板、验收与实际本地测试结果。
- tests/：本地隔离测试；邮件和AI结构化输入由测试代码提供，不声称真实模型或邮箱执行。
- examples/：任务/联系人/多指令样例，不会自动写入生产空间。

## 保守处理与当前限制

1. 邮件匹配有业务锚点硬验证；纯同义改写而无共同业务锚点时会进入待确认，避免错误覆盖。
2. 自动新增正式任务要求管理员下达发件人白名单、明确下达语句、任务/部门/ISO截止日期可在原文核对。其他自然语言新事项由管理员确认后新增。
3. 附件内容可实际本地提取；自动合法下载取决于平台能力。提取结果由宿主AI提出管理员批量操作，不冒充正文自动回写。
4. 主台账保留最新AI结论；无AI适配器则明确待研判，不使用规则拼接冒充深度AI。
5. 报告是当前台账快照，未实现全量长期历史趋势。详细事件只保留72小时。
6. xlsx和docx可用；扫描PDF OCR、旧xls/doc转换、Windows兼容、外部手工增表及schema迁移不在当前已验证范围。
7. 当前没有预授权邮箱能力证明；内核默认保留待发送，只有企业可信适配器通过平台通讯录/本次授权后才调用真实发送。

以上是实际实现边界，不能把本地验收等同于满足全部MobileWork上线条件。
