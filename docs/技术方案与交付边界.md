# V1.2技术方案与边界

默认路线：MobileWork自身大模型推理 → 自然语言调用cmcc-mail → 原生结果回写 → 确定性内核落账/统计/图表。没有额外模型API，没有本项目自建邮箱API，也不要求Python邮箱桥接模块。

新增native.py实现可中断恢复的原生阶段编排、邮件与分析回写、报告文字接收、发送委托和文本回执校验。reports.py将MobileWork撰写的有引用复盘实际嵌入Word。__main__.py默认full/sync/scan/warn进入原生协作。SKILL.md指挥宿主持续执行；不是让命令行程序自己调用一个不存在的平台API。

可在当前Linux环境验证：真实Excel跨次运行、任务/统计/预警队列、10份图表报告、原生交接检查点、回执幂等及异常恢复。模型结果和cmcc-mail回复在本地测试中仍是显式模拟输入，不能证明目标平台的实际分析效果或真实收件箱投递。

尚须在MobileWork实际验收：脚本与依赖可用性、宿主重启持久化、自身模型质量、自然语言Skill委托、附件可获取性和本次发送权限。不能因本会话不能调用你的MobileWork就认定平台没有这些功能。

未覆盖的可选能力：内置扫描PDF OCR、旧xls/doc转换、Windows原生兼容、所有恢复副本的统一72小时脱敏清理。可使用平台合法原生文档能力取得可处理资料，但当前包没有实测这些扩展。
