# 督办盯梢小助手 V1.1 端到端审计与验收报告

日期：2026年10月17日，北京时间。结论：**可执行本地内核已修复并验证，但项目整体尚未完成真实MobileWork生产链路。** 不能据SKILL.md功能描述、函数存在或模拟回执认定完成。

## 审查范围与方法

逐项检查duban的6个运行文件、全部tests、tools、schema、提示词、部署文档与依赖配置，静态盘点见evidence/review-inventory.json。原24项测试重新执行通过，但不足以证明端到端能力。新增缺陷复现与回归后，50项测试通过，详见evidence/regression-50-tests.txt。

另运行tools/run_acceptance.py，37次独立命令行调用完成双轨流程：52项真实本地文件检查、13项模拟宿主检查通过，0失败。全部任务数据为合成测试样本；“实际运行”只证明当前Linux环境内代码/文件行为，不代表真实公司业务、真实模型或真实邮箱。

## 3. 受平台接入、权限或能力资料限制，尚未验证

当前会话未接入MobileWork，runtime capabilities为空，也没有平台认证/内部邮箱/宿主模型凭据。没有证据表明平台“不支持”，只能说未接入、未验证。

- MobileWork执行Python、文件锁、原子替换、符号链接、依赖及中文字体是否可用。
- 平台工作空间经自动任务、宿主重启后是否仍保持固定台账。
- cmcc-mail实际版本、mobilework_auth_request参数和跨Skill认证顺序。
- 真实邮件查询、正文、附件合法下载及Excel/Word附件投递、收件箱实际收到。
- 宿主原生大模型的语义匹配准确率、歧义处理和深度拖延原因质量。
- 企业通讯录核验、逐次确认、正式预授权/服务级发送是否受支持。
- 真实邮箱超时后以消息ID/幂等关联核实已发送，及真实网络异常恢复。

解除条件：提供真实cmcc-mail SKILL.md与工具规范、可调用的MobileWork测试环境、经确认的测试收件人与合法授权；由可信适配模块执行实际工具后记录非敏感平台回执和收件箱证据。

## 4. 尚未实现

1. **生产MobileWork/cmcc-mail原生工具绑定模块。** 现有adapters.py只实现合同调度、授权门禁和发送状态机；它不包含真实认证、查询、下载或发送工具绑定。资料未提供，不能编造接口补齐。
2. **实际宿主AI工具绑定。** plan_admin/plan_feedback/analyze的提示词、结构化规范和验证器已具备，但生产调用函数没有实现。测试fixture不构成这项实现。
3. **由宿主AI生成整篇报告叙事与智能复盘。** 当前Word是确定性统计正文、图表与已有结构化研判的嵌入；不是实际调用模型自由撰写的综合复盘。
4. 扫描PDF OCR、旧xls/doc转换及Windows原生兼容目前未实现。xlsx、docx和文本型PDF有实际解析代码。

前3项属于整体业务目标未完成部分。当前无法仅靠本会话补齐真实平台模块；须取得真实接口和受支持执行环境后继续实现、测试。不能因提供了SKILL.md、提示词和合同就标为完成。

## 已复现并修复的问题

| 问题 | 修复与复测 |
|---|---|
| 相同进展重复更新，旧通知被作废 | 无语义变化返回无变更，历史/通知不改；邮件时间水位单独保存 |
| 空截止日期/非法文本可损坏后续报告 | 关键字段非空、类型/日期/非法字符校验，主台账重读校验，不静默丢弃未知表 |
| 空字符串AI证据通过 | 非空白原文验证，AI结果预校验；不把前次AI推测作新证据 |
| 同秒更新仍沿用旧AI结论 | 业务字段指纹判定有效性，更新风险置未研判，不触发旧AI预警 |
| 重跑报告产生5封额外通知 | 日期+业务快照指纹复用文件；重复入队0，缺源/旧报告拒绝发送 |
| 报告发布后台账save失败可能不一致 | 发布日志、提交/回滚回调；真实进程退出后自动恢复，故障注入测试保留旧版 |
| 同时间矛盾反馈按遍历顺序覆盖 | 进入待确认，不擅自判定最新 |
| 80%可能从180%中误匹配 | 按完整数值token验证 |
| 仅看附件路径而未解析 | sync实际提取原文并标source_id；缺附件阻止游标及预警，恢复后重跑 |
| 分页/拉取异常及返回None处理不足 | 自动分页、非推进游标阻断、失败页保留；非法发送结果记未知并继续其他项 |
| 旧版研判及旧待发报告可能沿用 | 无法验证指纹的旧研判转未研判；已入队报告发送前再次验证最新台账快照，陈旧则失效 |
| 未区分模拟成功 | 回执执行模式和摘要计数拆分；fixture永远simulation |

具体原始复现对照见defects-before.json与defects-after.json；所有修复有回归覆盖。原24项通过仍存在上述缺陷，证明不能仅以旧测试数量判断项目完成。

## 部署结论

可交付V1.1本地内核、报告生成及复现工具供评审；不批准无人值守企业邮箱上线。操作见部署操作说明_V1.1.md。拿到真实平台规范和测试环境后，应实现第4类前3项，再完成第3类真实验收，才能重新判定项目整体完成。

## 保留范围补充

72小时自动清理目前针对最近72小时历史记录表。主台账最新结论、发送记录、待确认事项及上一有效恢复备份按恢复和审计需要保留；未实现所有副本的统一72小时脱敏清理。如果部署要求全部历史副本也受72小时限制，这项尚未满足，需要额外制定并实现保留策略。
