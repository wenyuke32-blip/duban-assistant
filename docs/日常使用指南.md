# 管理员日常使用

只有完成真实宿主AI/邮箱绑定和平台验收后，才能在MobileWork用自然语言调用。本包当前没有生产绑定模块；SKILL.md仅给出宿主应遵循的操作规范。若尚未完成宿主部署，可在项目目录直接运行下列真实本地命令；将示例工作空间替换成同一个持久化绝对路径。

```bash
python -m duban init --workspace ./我的督办数据
python -m duban add --workspace ./我的督办数据 --file examples/新增任务.json
python -m duban query --workspace ./我的督办数据
python -m duban reports --workspace ./我的督办数据
```

初次配置四部门主管和管理员：按examples/联系人.json填写真实姓名邮箱，逐部门执行contacts；四行管理员邮箱应相同。不猜邮箱，不把示例example.invalid当作真实地址。

| 常见表达 | 处理方式 |
|---|---|
| 新增一项政企部督办，月底前完成企业信息摸排 | 宿主AI补齐确定日期；缺关键依据时请管理员说明 |
| 政企部专线项目施工完成，正在等待验收 | 唯一匹配→待验收；不编造百分比 |
| 预计28日完成，原截止20日 | 预计日期变为28日，原截止保留20日，之后继续计逾期 |
| 同步督办邮件 | 真实邮箱查询、拆分、核对、增量更新；有歧义进待确认 |
| 查询网络部风险任务 | query部门筛选与高风险筛选，返回真实台账数据 |
| 把网络部主管邮箱修改为某地址 | contacts保存，后续邮件使用新邮箱；旧通知需重新核对授权 |
| 上次已办结的某项目还有资源未交付 | 明确匹配原ID重开，重开次数+1，保留原截止 |
| 删除某事项 | 管理员明确且唯一匹配后delete；同名多项先确认 |
| 生成部门周报 | 一次生成所有部门及管理员的10份配套报告 |
| 发送部门周报 | 先入队，再通讯录验证和本次发送授权，成功才记已发送 |

batch支持一次多个操作，格式见examples/多指令.json。先query取得真实ID，再编辑更新文件。查询可用 `--department 政企部 --risk`；`outbox`查看待发送及未知状态；`pending`查看歧义、缺少关键字段和失败项。

resolve处理待确认：管理员核对邮件/附件原文和任务ID后，提供正确的操作数组。例：`python -m duban resolve --workspace ./我的督办数据 --pending-id 待确认ID --file 已核实操作.json`。核实为无关事项可提交空数组，仅标记该项已处理；不发生任务修改。部分操作失败则整个确认不结案，避免半确认。

宿主AI未接好时，context读取上下文→由宿主大模型按prompts生成JSON→batch/analysis写入。没有AI能力时不会自动虚构研判，只列出需研判任务ID。扫描结果“暂无高风险”不代表所有任务已完成AI研判。

Excel导入支持标准列和常见中文别名。陌生列可由宿主AI提出映射，管理员核实后通过 `--mapping` 提交，格式：{"事项":"任务名称","部门":"主责部门","截止":"原定截止日期"}。只支持xlsx，明确ISO日期或Excel日期单元格；文本日期无法确定年份/月日时保留待确认。精确重复跳过，相近任务先待确认，不因相似名称覆盖。

报告在固定workspace/reports内。Excel含真实任务清单、状态/风险/完成图、原因分类、逾期和协办清单、责任人/部门统计；Word嵌入图表及已有有效AI结论。没有AI结论会明确写尚未研判，不伪造专业分析。没有历史数据不生成趋势。

完整自动流程使用 `python -m duban full --workspace 固定路径 --adapter 已验证模块名`。不要在生产自动任务里加--local；该选项仅用于管理员明确要求的离线验证。没有真实邮箱接口/授权时只能本地管理和生成报告，不能无人值守发信。
