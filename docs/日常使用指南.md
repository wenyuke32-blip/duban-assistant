# V1.2管理员日常使用

直接在MobileWork说自然语言。AI分析使用MobileWork当前会话自身的大模型；邮件直接委托cmcc-mail。后台JSON和脚本步骤由宿主完成，不用管理员写代码、配API或手填JSON。

首次说明固定台账目录、四部门主管姓名/邮箱、同一管理员邮箱；如有现成Excel，上传并说“导入督办台账”。不要把空模板覆盖到已有台账。

常用表达：

- “新增一项政企部督办，月底前完成企业信息摸排。”缺少可确定日期或责任资料时补充，不凭空猜测。
- “政企部专线已经完成施工，正在等待验收。”唯一匹配后更新为待验收，不估算完成百分比。
- “预计28日完成，原截止20日。”只变预计日期，原截止保留，超20日仍计逾期。
- “同步督办邮件。”助手让cmcc-mail查信、读详情及合法取得附件，自身理解后校验回写，歧义保留待确认。
- “扫描督办风险。”MobileWork自身分析事实、可能原因、证据、协调事项及具体措施，不把推测写成查实事实。
- “生成部门周报。”生成四部门和管理员共10件含图表与自身模型复盘的报告；仅生成不自动发送。
- “发送部门周报。”通过cmcc-mail分别发对应两件，综合报告只给管理员；遵循该Skill的确认/授权流程。
- “执行完整督办流程。”自动继续同步、分析、复盘、生成、委托发送及实际摘要。
- “继续上次督办流程。”从原生检查点继续；未知发送先查证原调用，不重发。
- “把网络部主管邮箱改为……”保存真实地址，后续使用新地址，不猜邮箱。

原始任务唯一ID、原截止日期、累计延期和重开次数长期维护。已完成/已取消归档并停止预警。管理员明确删除且对象唯一才删除，主管邮件不能物理删除。

收到需要确认的cmcc-mail提示，按它自身流程确认；收到未知结果，不重复点发送。助手报告“cmcc-mail明确返回成功”也不等于已经从收件箱验证收到。

更详细部署、恢复和后台原生入口见MobileWork原生部署_V1.2.md。实际平台验收结论以端到端验收报告.md为准。
