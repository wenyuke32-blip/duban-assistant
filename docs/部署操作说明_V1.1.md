# 部署操作说明 V1.1

本包是修复后的可运行本地内核，不是已经接通企业平台的成品。请先读端到端验收报告的四类结果。

## 一、下载和本地准备

从仓库downloads下载duban-assistant-v1.1.zip，解压到可读写目录。运行环境要求Python3.10+、Linux/POSIX文件锁、原子替换/符号链接、中文字体及requirements.txt中的依赖。当前只验证Linux，未验证Windows直接执行。

进入解压后的项目根目录：

```bash
python tools/check_environment.py
python -m duban doctor --workspace ./workspace-data
python -m unittest discover -s tests -v
python tools/run_acceptance.py --output ./acceptance-run
```

acceptance-run必须是新的空目录。最后一条会真实写本地Excel/Word并运行显式模拟宿主；不会联网调用模型或邮箱。看到模拟发送回执不能认为实际发信成功。生产workspace-data不要作为验收目录。

如果依赖缺失，只在平台正式允许安装时执行：

```bash
python -m pip install -r requirements.txt
```

本地依赖可用不证明MobileWork允许安装或运行Python。check_environment探测只覆盖当前执行环境，不涵盖平台重启持久化。

## 二、建立固定台账

选择一个固定、受企业访问控制保护的绝对路径。以下路径仅为示例，须替换为平台实际持久化路径：

```bash
python -m duban init --workspace /持久化目录/督办数据
python -m duban import --workspace /持久化目录/督办数据 --file /实际上传文件/原台账.xlsx
python -m duban query --workspace /持久化目录/督办数据
```

每次运行传相同路径。初始化不覆盖已有任务；表头/任务ID/关键字段/版本损坏时报错，不重新初始化。未知工作表拒绝静默丢弃。不同列名可通过mapping JSON或宿主AI映射。首次创建为空，不填示例业务。

按examples/联系人.json配置四部门真实主管及同一管理员邮箱。example.invalid仅测试，不是真实收件人。新增/更新JSON见examples；close/reopen保留同一任务ID与原截止日期。

## 三、只使用已验证的本地功能

```bash
python -m duban add --workspace /持久化目录/督办数据 --file /实际上传文件/新增任务.json
python -m duban reports --workspace /持久化目录/督办数据
python -m duban pending --workspace /持久化目录/督办数据
python -m duban outbox --workspace /持久化目录/督办数据
```

reports生成四部门和管理员各xlsx/docx，共10件。相同日期同一业务快照复用文件，不产生新的报告邮件。原始Excel中百分比按0至100填写，缺失不自动估算。

没有真实适配器时sync/dispatch明确受阻，full暂停新预警。管理员可用--local仅验证本地队列与报告，输出不会表示真实同步/发送成功。

## 四、完成尚缺的MobileWork与cmcc-mail集成

需要的资料：实际安装版本的cmcc-mail/SKILL.md、MobileWork原生工具参数与执行权限、固定目录重启后的持久化证据、经管理员确认的测试收件人和平台正式授权机制。

企业部署人员根据docs/邮件与宿主适配.md，将实际宿主工具绑定到可信Python模块。当前包没有生产绑定模块，不能直接用一个名称代替实现。不要复制tests/fixture_adapter.py到生产；它只是脚本化模拟，不调用模型或邮箱。

适配模块声明EXECUTION_MODE="production"仅是来源标记，不会创建任何授权。authorize必须真实调用企业通讯录及平台本次确认/正式预授权；send必须返回平台真实消息ID；lookup_sent必须核实未知结果。不得把联系人确认当持续发信许可。

```bash
python -m duban doctor --workspace /持久化目录/督办数据 --adapter 企业实际实现的模块
python -m duban sync --workspace /持久化目录/督办数据 --adapter 企业实际实现的模块
python -m duban scan --workspace /持久化目录/督办数据 --adapter 企业实际实现的模块
python -m duban full --workspace /持久化目录/督办数据 --adapter 企业实际实现的模块
```

上述模块名是占位说明，必须替换为已实现模块；doctor显示函数可调用不代表接入成功。先按验收清单使用真实测试邮箱执行搜索、详情、附件下载、语义多任务拆分、AI质量、通讯录验证、确认发送、两附件投递和已发送核对。记录实际回执及收件箱证据，禁止只看适配器返回。

平台没有正式无人值守授权时，保留待授权队列，由管理员逐次确认后发送。不要绕过cmcc-mail安全规则。通过真实验收前不要配置生产自动任务；通过后由管理员在MobileWork配置，项目不部署定时器。

## 五、恢复与重跑

```bash
python -m duban reconcile --workspace /持久化目录/督办数据 --adapter 企业实际实现的模块
python -m duban recover --workspace /持久化目录/督办数据
```

reconcile先核实发送中/未知项；未知不能直接重发。只有平台明确没有接受的失败才可重试。

recover只能由管理员在停止自动任务后运行：先验证上一有效备份，保存现有损坏文件副本，再原子恢复。可能回退一版，请特别核对已发送记录和邮件去重记录，不能在回退后盲目全量发信。

报告发布中断由.report-publication.json自动恢复：若台账未提交，恢复旧报告；若台账已提交，保留新报告并清理旧版。正常状态只保留最新10件；崩溃窗口可能暂时保留两代以保证恢复。不是对硬件断电/跨机器网络文件系统作保证。

升级V1.0前先在受控位置备份完整生产工作空间；不要用空模板覆盖。V1.0旧研判缺少业务指纹，需要重新扫描后才视为当前有效。主台账schema仍为1，程序新增配置键，不改变既有表头。
