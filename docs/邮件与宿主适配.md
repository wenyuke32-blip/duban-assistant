# MobileWork原生AI与cmcc-mail自然语言协作

V1.2默认不需要Python模型/邮箱适配器。MobileWork的当前Agent使用自身大模型，直接用自然语言调用cmcc-mail。不要让管理员另建API或先交接接口参数。

宿主负责分析管理员请求、邮件语义、延期原因和报告复盘；内核负责数据与可复核规则。宿主把自己分析的结构化结果写入native-mail/native-analysis/native-report-text，结果实际进入固定台账与Word文件。

cmcc-mail负责真实邮件搜索、读取、附件与发送；其认证、通讯录和授权规范由它运行时执行。native-next-send给出自然语言委托，宿主调用后用native-send-result保存真实回复。看不到实际结果不能填成功。message_id可缺省，不能伪造；内部handoff_id只作去重关联，不是认证或平台证明。

若cmcc-mail要求确认，按其规范继续原调用。若结果未知，只查询原发送，不再发一遍。联系人维护不是长期发送授权。附件能力以cmcc-mail实际执行结果为准，不能把“准备下载”当已获取。

自然语言示例见prompts/cmcc_mail_calls.md；完整执行步骤见MobileWork原生部署_V1.2.md和SKILL.md。旧--adapter入口仅兼容既有程序桥接，不是V1.2的必需部署项，也不应再因未编写桥接而阻塞原生流程。
