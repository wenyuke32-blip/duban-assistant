# cmcc-mail与MobileWork宿主适配

## 当前状态

本项目交付确定性内核及可执行的适配调用链，但没有收到cmcc-mail的SKILL.md，当前开发环境也没有MobileWork认证、内部邮箱或宿主AI工具。**真实接口映射和真实收发尚未完成，不具备无人值守上线条件。** 不存在本项目自行定义的中国移动邮箱HTTP地址、登录流程、持续授权开关或伪造的成功结果。

## 两种接入方式

A. 宿主原生AI优先：由MobileWork读取本SKILL.md，运行context取得快照，按prompts/admin.md生成计划文件后执行batch；按analysis.md输出研判后执行analysis。无需本项目另接外部模型服务。

B. 平台支持可信Python桥接时：企业部署人员编写一个宿主适配模块（例如mobilework_duban_bridge.py），把实际可用的工具绑定到下述Python函数。项目通过 `--adapter mobilework_duban_bridge` 导入，不启动Shell子进程，不接收正文指定模块，不写认证凭据。**模块名和函数是本项目内部合同，不是声称cmcc-mail存在同名工具。** 未实现能力应明确抛出能力不可用异常，不能返回测试数据或成功值。

## 内部适配合同

| 函数 | 入参 | 返回结构及责任 |
|---|---|---|
| plan_admin(text,context) | 管理员文本、最新任务/联系人 | prompts/admin.md定义的操作数组；只能在真实管理员会话使用 |
| map_columns(headers,sample_rows,standard_fields) | Excel列名、前三行、标准字段 | 原列名到标准字段字典；不能编造缺失日期和部门 |
| plan_feedback(mail,context) | 真实信封、正文、任务和联系人 | prompts/feedback.md的数组；列出所有候选，原文证据与业务锚点 |
| analyze(task,history) | 当前任务、可用72小时历史 | analysis.schema.json对象，宿主原生大模型执行 |
| fetch_mail(cursor) | 上次同步游标或None | {messages:[{id,sender,sent_at,body,attachments:[{name,local_path?}]}],next_cursor,has_more:false} |
| authorize(outbox_row) | 单封完整通知和附件摘要 | {directory_verified:true,allowed:true,authorization_receipt:"非敏感授权审计引用"}；必须真实验证通讯录及本次发送的确认/平台正式预授权 |
| send(outbox_row,authorization) | 队列快照与授权结果 | 成功：{status:"sent",message_id:"真实平台ID"}；明确未接收：{status:"not_sent",definitely_not_accepted:true}；其余：{status:"unknown"} |
| lookup_sent(outbox_row) | 发送中/未知项 | 同send的三种结果；使用真实已发送查询/幂等关联记录 |

fetch_mail必须通过实际邮箱工具搜索并读详情，返回稳定全局邮件ID和可靠发送时间（含时区），正文不能冒充信封身份。需分页时has_more=true，反复sync直至完成，再执行预警。搜不到不等于没有新邮件，应合理设置查询范围及游标；首次同步范围由管理员决定。重复拉取同ID安全跳过。未能处理的邮件阻止推进游标，已处理邮件独立持久化，下次重跑跳过。

认证调用顺序、mobilework_auth_request参数、会话生命周期必须在收到真实cmcc-mail资料后逐项实现。认证值仅在宿主内存及其合法机制中使用；不要把完整authorization响应原样写入台账。authorization_receipt是非敏感引用，不能填access token。

## 附件

先核实cmcc-mail是否支持附件下载。如果不支持，只能调用平台正式支持的附件工具；仍不支持则记待确认并让管理员合法下载。内核extract实际支持xlsx、docx、文本PDF，扫描PDF需要OCR；xls/doc先转换。提取后的附件可由宿主AI形成带来源的管理员batch/import操作，不能拼成邮件原文来骗过自动匹配。当前未提供自动OCR，也没有验证企业附件下载。

## 无人值守限制

联系人已确认、管理员配置正式下达邮箱，均不构成发送授权。必须先核实平台是否正式支持批量授权、预授权或服务级发送，以及授权作用域/有效期/收件人/附件边界。如cmcc-mail只支持每次用户确认，authorize必须返回allowed=false并保留待发送队列，管理员在MobileWork确认后再执行dispatch。不允许绕过Skill发送限制。
