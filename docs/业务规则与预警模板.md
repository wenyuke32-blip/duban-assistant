# 确定性业务规则

办理状态与风险分开：未开始、办理中、受阻、待验收、已完成、已取消；风险：未研判、低、中、高、紧急。

已完成及已取消移入已办结表并停止预警。已取消仍计任务总数但排除完成率分母。完成率=已完成/有效任务；按期完成率=实际完成日期不晚于原截止的已完成/已完成。空分母显示空值/无可计算数据。逾期只统计当前在办任务；已完成即使晚完成也不再计当前逾期，但不计按期完成。日期按北京时间自然日，截止当日尚不算逾期。

固定时间节点仅在剩余7、3、1天生成相应通知；错过节点不补造历史通知。超过截止每天生成一次逾期通知。AI首次高/紧急风险或升级可产生额外通知；同一任务、原截止、重开周期、等级、收件人不重复。风险从高升紧急各一次，同等级反复升降不重复。已发送或结果未知都阻止同键再次入队；旧通知因业务变化失效后，允许按最新进展重新生成尚未发送的通知。原截止经管理员正式调整会产生新的节点周期；主管反馈无权更改。

提醒优先责任人联系邮箱，未配置则主管；紧急、逾期及AI高风险同时升级给主管和管理员，地址相同自动去重。缺合法邮箱进入待确认。不要用“已入队数量”代替实际发送数量。

通知模板：

```
主题：督办通知｜{预警等级}
任务名称：{台账值}
主责部门/责任人：{台账值}
原截止日期：{原定截止日期}
预计完成日期：{明确反馈的预计日期，未提供则注明}
最新进展：{台账最新有效进展}
当前AI风险：{台账值；未研判就注明}
可能原因（待核实）：{有效AI结论}
判断依据：{可查原文}
建议：{针对性措施}
反馈要求：请反馈真实进展、阻塞事项及下一步计划。
```

原文的延期事实与AI推测分开。未知发信状态先核实，明确未被平台接收才可再次dispatch。每次成功立即保存平台消息ID和时间；进程在发送后回写前中断会留下发送中，下次不会自动重复发送。

报表模板由reports.py实际生成：总况、进展、风险研判、协调与建议、下阶段跟踪、协办及统计口径；不是用静态数字替代台账。
